## 3. Claude 웹 검토와 확정 지시서의 반영 사항

사용자 제공 v2.0 지시서는 Claude 웹 사전 검토 반영을 명시하고, 협업 규칙 구조,

확정 지시서와 저장소 Diff에서 확인한 채택·보완 사항은 다음과 같다.

- 협업 규칙의 단일 정본, 일반·경량 경로, Claude Code 읽기 전용 감사와 사용자
  Commit·Push 원칙을 반영했다.
- Attempt3 승인 경계와 27B 실행 경로를 문서에 명시했다. 2B의 Norm-matched Null,
  Matched Control, 선택 편향 보정과 독립 Held-out 평가를 실행 전 설계 항목으로 채택했다.
  후보 수만으로 선택 보정을 확정하거나 이미 관측한 Growth 세 문항에서 일반화 정밀도를

- 문서 작업의 범위, 보존 조건과 Git·Markdown·SHA 검증 요건을 반영했다. 개별 Claude 웹
  원문과 GPT의 의견별 판정 원문은 제공 자료에서 확인되지 않았다. 회차별 일자·대상 SHA와
  Claude 웹의 실제 조건부 GO 발언은 확인 대기다. GPT 최종 검토도 대기 상태다.
  [Claude 웹 검토 기록](../reviews/2026-11-21_phase5d3b_claude_web.md).

## 4. Growth019 해석 정정과 B 단계 주 지표

사용자가 전달한 Claude 웹 정정 사항을 10월 30일 일지, 연구 보고서와 Growth019 Pilot
Audit에서 대조하고 계획서의 B 단계에 반영했다. 기존 제한 생성에서 Baseline은
`55 days`(Correct)였고, 30908 +8은 `28 days`(Lure)로 전환됐다. 첫 분기 Raw와 Processed
Margin은 각각 0이며 저장 Logit은 동률이었다. 30908 +8.5와 12207 +8의 첫 분기 Raw Margin은
각각 +0.125와 +0.625였고 둘 다 Lure가 생성됐다. 12207은 비교 Feature이며 중립성은
검증되지 않았다. Hagendorff CRT의 39.5%→82.5%는 30908 탐색에 사용한 데이터셋의
in-sample 정답률로 표시했다. Fresh v2는 Baseline 54.5%, +7 55.0%, +8 48.5%로,
유형별 개선과 악화가 함께 관측됐다.
[10월 30일 일지](2026-10-30.md),
[10월 30일 연구 보고서](../reports/MindScopeX_연구진행현황_2026-10-30.md),
[Growth019 Pilot Audit](../audits/2026-10-30-growth019-minimal-pilot/report.md).

B 단계의 독립 평가 Primary Metric은 문항별 연속 `Δmargin = intervened_margin - baseline_margin`으로
정의했다. 양수는 Lure 방향, 음수는 Correct 방향이다. 공통 기대 방향을 가정하지 않고 양측 검정
또는 데이터셋별 사전 지정 방향을 사용하도록 했다. 생성 답 전환은 보조 지표로 두고 정확한 동률과
동률 근처(`|margin|`이 작은 경우)를 구분해 표시한다. 양측 Null 판정, 다중 비교·선택 보정,
최소 실질 효과와 Matched Control 기준은 B 실행 전에 확정해야 한다. GO는 독립 문항의 연속
효과와 해당 기준을 충족할 때만 가능하며 NO-GO와 INCONCLUSIVE도 사전 정의를 따른다.
[Phase 5-D-3B 범위 계획](../plans/2026-11-21_phase5d3b_scope_plan.md).

## 9. 독립 감사 후속 정정 및 Claude 웹 보완 의견 반영

기준 HEAD `3e5a9a9a0981340f260f959f7bfb53bf4bd6eb4f`에서 사용자가 전달한 M1~M4 통합
지시와 Claude 웹 추가 의견을 Scope Plan B에 반영했다. 이 절은 §4의 당시 기록을 보존한
상태에서 그중 Hagendorff 분류와 B 지표 표기를 정정한다.
[Phase 5-D-3B 범위 계획](../plans/2026-11-21_phase5d3b_scope_plan.md).

- **M1 — Hagendorff 평가 분류.** §4의 `in-sample` 표기를
  **MIXED / PARTIALLY EXPOSED — selection-contaminated split held-out evaluation**으로
  정정한다. Split Seed 0~4별 held-out 40문항 설계에서 고정 +7의 200슬롯에는 고유 문항
  112개가 있었고 Seed 쌍별로 9~14개 문항이 겹쳤다. 평가 결과도 Feature·Coefficient 선택에
  사용됐다. +8의 39.5%→82.5%(+43.0%p)는 기존 보고값이다. 접근 가능한 Seed 0을
  재계산한 값은 17/40→33/40, 즉 42.5%→82.5%(+40.0%p)였다. 전체 +8 원본 재계산은
  `NOT VERIFIED`이며 120개 조건의 완전성도 미확정이다. 독립 데이터셋 일반화 근거에서
  제외했다. [10월 1~10일 일지](2026-10-01_2026-10-10.md),
  [10월 11~18일 일지](2026-10-11_2026-10-18.md).
- **M2-A — Margin 지표 구분.** B의 문항별 주 지표를
  `steer_shift = intervention_margin - baseline_margin`으로 명시했다. 기존 `effects.py`와
  `research.py`의 `margin_delta`는 반대 부호다. 동일 문항·후보·측정 프로토콜에서 동일한
  Baseline·개입 Margin 쌍을 쓸 때만 `steer_shift = -margin_delta`이며, 기존 값을 가져올
  때 한 번만 변환한다. Ablation과 Positive Steering, Teacher-forced Margin과 실제
  Generate First-Divergence Margin의 출처를 각각 기록한다. 기존 연구 설계 문서의 지표
  정의는 유지했다. [Margin 코드](../../src/mindscopex_analysis/effects.py),
  [기존 연구 설계](../../docs/study_design.md).
- **M2-B — Matched Control.** `control_specificity_rows`는 원래 Hostile의 Correct/Lure
  문자열을 두 조건에 적용해 `specificity_gap = hostile_delta - control_delta`를 계산한다.
  기존 계산과 결과를 보존했다. 일부 Hagendorff와 Fresh v2 Control에서 Hostile Lure 값은
  Control의 의미상 정답이므로, 양의 Margin이 그 정답을 선호하는 경우가 있다. 이 비교는 원래
  문자열의 개입 효과를 측정한다. 의미상 정답률 개선과 Feature 특이성의 확증에는 별도 근거가
  필요하다. 새 Control 분석은 답안 매핑과 재매핑 필요성, Matched Control과 Random Direction
  Null의 역할 및 비교 방법을 사전에 확정한다. [Specificity 코드](../../src/mindscopex_analysis/research.py).
- **M3 — 독립 확증 평가.** `hagendorff_crt`, `crt_fresh_v2`,
  `crt_fresh_v2_rate_order_pilot`를 주 평가에서 제외했다. Hostile·Matched Control·동일
  원본·표현 및 답안 순서 변형·사실상 같은 Template까지 노출을 검토한다. `crt7_classic`,
  `crt2`, `crt_fresh_v1`은 문항 ID·정답/Lure 구조·Template·의미 중복과 선택 노출 검증이
  필요한 후보로 기록했다. Fresh v2의 Growth019/004/016 Cross-Case는
  `Secondary / Exploratory / Reproduction`에 배정했다. 기존 계획과 Artifact를 보존하며
  해당 분석은 독립 문항 일반화의 근거에서 제외한다.
- **M4 — B의 주 검정통계량.** 문항별 `steer_shift`를 유지하고, 전체 문항에 적용할
  Primary Test Statistic은 부호 있는 평균·절댓값 평균·방향과 크기를 함께 고려하는 사전
  지정 분석 중에서 실행 전에 결정하도록 했다. 관측 조건·Null·비교군에 동일한 계산 규칙을
  적용한다. 문항 수, 효과 크기, 신뢰구간, 양측 Null, 다중 선택 보정, 동률 근처 임계값과
  GO / NO-GO / INCONCLUSIVE 기준은 사전 확정 항목이다. 이번에 수치를 추가로 확정하지 않았다.
- **Fresh v2 Rate.** 기존 정답 수는 Baseline 54/66, 30908 +7 1/66, +8 2/66이다.
  답변 형태·출력 토큰·선택지 위치·표면 문자열·Template의 영향을 검증할 가설로 기록했다.
  B 실행 전 의미상 정답과 Lure의 구별, 실제 Margin과 Behavioral 정답률의 관계, 동일 조건의
  Matched Control 및 Random Direction 비교 방법을 확정한다. 형태 편향의 인과 여부는
  미검증이다. [Fresh v2 유형별 관측](2026-10-23.md).
- **L2 — 운영 규칙 잔여 문구.** 기존 §2의 Commit 담당 표기와 §8의 Commit 관련 문구가
  남아 있다. §12.1의 우선 적용 조항에 따라 사용자가 Commit·Push를 맡는다. 1~11절은
  보존했으며, 과거 문구의 정리 여부는 별도 운영 규칙 정비까지 보류했다.
  [운영 규칙](../../MINDSCOPEX_WORKFLOW_RULES.md).

Attempt3 실제 A100 Runtime 5단계, 승인 소진 여부, 서버 세션 종료는 미검증 상태로 남아 있다.
B의 사전 통계 기준과 C의 가용성·비용은 실행 전에 별도로 확정한다. 이번 보완에서 GPU·Colab

## 10. Claude Code 재감사 N1~N4 후속 정정

사용자가 전달한 Claude Code 재감사 판정은 **CONDITIONAL GO**다. 기존 M1~M4, Fresh v2
Rate, L2의 PASS를 유지한다. 이번 후속 보완은 기준 HEAD
`3e5a9a9a0981340f260f959f7bfb53bf4bd6eb4f`의 Scope Plan과 이 일지에 한정했다.

- **N1 — Matched Control 전체 적용.** §9의 ‘일부’를 ‘두 데이터셋 각각 전 문항’으로
  정정한다. 원본 JSON에서 `hagendorff_crt`와 `crt_fresh_v2` 각각 150/150문항에
  `control_question`이 있고, 문항별 메타데이터와 `docs/datasets.md`에서 모든 Control의
  의미상 정답이 Hostile의 `lure_answer` 값임을 확인했다. 기존 `control_specificity_rows`는
  두 조건에 동일한 Hostile `correct_answer`와 `lure_answer` 문자열로 Margin을 계산한다.
  양의 Margin은 Hostile의 의미상 오답 또는 Control의 의미상 정답인 그 문자열 쪽 선호를
  뜻한다. 기존 `specificity_gap = hostile_delta - control_delta`와 결과를 보존한다.
  의미상 정답률 개선은 조건별 정답을 기준으로 한 별도 평가 항목이다.

  [데이터셋 문서](../../docs/datasets.md).
- **N2 — `results/` 무결성 검증 범위.** §9의 795개 SHA-256 일치는 M1~M4 문서 보완
  직전과 직후에 같은 세션에서 `python3 -B`의 `Path.rglob`과 `hashlib.sha256`으로 대조한
  기록이다. 비교 범위는 그 편집 구간이다. 이번에는 `git ls-files -- results`로 추적
  653개를 확인했고, `git diff --exit-code HEAD -- results`로 해당 파일에 변경이 없음을

  매니페스트가 확인되지 않아 과거 무결성 보존 여부를 **NOT VERIFIED**로 기록한다. 새
